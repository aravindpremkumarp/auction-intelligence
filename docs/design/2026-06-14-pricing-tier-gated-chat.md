## Problem Statement

The app offers conversational chat to all users with no usage limit and no way to
pay for more. To launch a sustainable tier, we need three things working together:

1. A **free-tier quota** on chat that is correct under concurrency and survives
   restarts.
2. A **payment flow** (Razorpay) that activates a paid tier, with the webhook — not
   the browser redirect — as the source of truth.
3. **Test coverage** that proves all of the above before launch and cannot silently
   rot in CI.

This document records the engineering decisions from the plan review. It is the
reference for implementation.

## Decisions

| ID  | Area              | Decision |
|-----|-------------------|----------|
| D1  | Quota storage     | Durable per-user counter on the Neo4j `User` node. Survives restarts; not per-instance (unlike the existing in-memory anon limiter). |
| CQ1 | Entitlement read  | Thread tier/entitlement through `UserOut` and reuse the existing user load. **No extra query** on gated requests. |
| CQ2 | Test coverage     | Faked Razorpay client + signed payloads across **all 27 paths**, **plus** one live test-mode E2E. |
| P1  | Counter increment | **Atomic increment-and-return, date-bucketed.** One Cypher write per free chat; correct under concurrent tabs; window reset is implicit in the bucket key. |
| D2  | Idempotency store | Processed webhook `event_id`s kept with a **90-day TTL** (time-based, not a count cap — a count cap can evict an id still inside Razorpay's redelivery window during a burst). |
| D3  | Verify-on-return  | The browser redirect verification is **non-authoritative**. On failure → show "payment pending"; do NOT grant entitlement. The **webhook is the sole source of truth** for activation. |
| D4  | Concurrency test  | `20 parallel requests, quota remaining = 1 → exactly 1 success / 19 rejects`. Must run against a **real Neo4j** (the atomicity lives in the DB; a mock would pass while proving nothing), so it belongs to the **live-E2E lane (CQ2)**. Assert `successes == 1` AND `rejects == 19`. |
| D5  | CI enforcement    | The live E2E is **required in CI** (red build if Razorpay test-mode keys are absent). **Skip-with-loud-warning locally** so contributors without keys can still run `pytest`. |

## Implementation Notes

### Quota counter (D1, P1)
Single atomic Cypher per free chat that increments and returns the new count:

```
MATCH (u:User {id: $uid})
SET u.chat_count = CASE WHEN u.chat_bucket = $bucket
                        THEN coalesce(u.chat_count, 0) + 1
                        ELSE 1 END,
    u.chat_bucket = $bucket
RETURN u.chat_count AS count
```

- `$bucket` is the current window key (e.g. `2026061410` for the hour). When it
  changes, the count resets to 1 in the same write — no separate reset job.
- Compare the returned `count` to the tier cap in Python. One round-trip, no race.

### Entitlement (CQ1)
Populate tier/cap onto `UserOut` at the existing user-load site so routers read it
from the already-hydrated user. No new DB call in the gated path.

### Webhook (D2, D3)
1. Signature-verify the payload (reject + test the rejection path explicitly).
2. Idempotency-check `event_id` against the store; skip if already processed.
3. Process → flip the entitlement bit. **This is the only place activation happens.**
4. Store `event_id` with a 90-day TTL.

The success redirect calls verify-on-return purely for UX. On failure render
"payment pending" and wait for the webhook.

## Test Plan (CQ2, D4, D5)
- Faked Razorpay client + signed payloads across all 27 paths, including the
  signature-rejection path.
- One live test-mode E2E with play money.
- Concurrency test (D4) against a real Neo4j: `20∥, remaining=1 → 1/19`.
- CI gate (D5): fail loudly if test-mode keys are absent in CI; skip-with-warning
  locally.

## Implementation Status

**PR 1 — quota + entitlement (this slice).** Implemented:
- Entitlement on `UserOut` (`tier`, `plan_expires_at`), derived lazily from the
  `:User.plan_expires_at` timestamp at the auth layer (`_derive_tier`) — no extra
  query (CQ1), no expiry cron (lazy fallback to free).
- Atomic, day-bucketed durable counter (`repository.bump_chat_quota`, P1)
  replacing the old in-memory per-user limiter.
- Tier-aware daily cap in `api/chat/router.py` (`_enforce_user_chat_quota`):
  free default 25/day, paid default 1000/day (both env-tunable
  `CHAT_FREE_DAILY_LIMIT` / `CHAT_PAID_DAILY_LIMIT`). Fails open on a Neo4j blip.
- `repository.grant_plan` lands the entitlement (for PR 2's webhook; exercised by
  tests now so the paid path is verifiable without payments).
- Tests: `tests/api/test_chat_quota.py` (paid bypass, lazy expiry, bucket reset,
  `/auth/me` tier) + updated `test_rate_limit.py`.

**Deferred to PR 2:** Razorpay order/checkout + webhook (D2/D3), the
`20∥ remaining=1 → 1/19` concurrency test against a real Neo4j (D4), and the
CI-required live E2E (D5). The free→paid quota split and `grant_plan` are already
in place, so PR 2 only adds the payment surface that calls `grant_plan`.
