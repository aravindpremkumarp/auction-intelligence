# Bank Auction Intelligence — Codebase Overview

AI-powered intelligence system for Indian SARFAESI Act bank property auctions.
Starts with a scraper for `eauctionsindia.com`, builds a Neo4j knowledge graph
of Tamil Nadu auctions, enriches it via OCR + vision-LLM extraction, and
serves a PydanticAI agent (FastAPI + single-page web UI) that scores, tracks,
and captures user feedback on investment opportunities.

## High-Level Flow

    scrape → clean/filter TN → load Neo4j → OCR+extract →
    verify/enrich → lexical graph → normalize → load enriched →
    embed descriptions → score/track → serve via API → feedback loop

## 1. Scraping Layer (`scrapers/`)

- `fast_eauctions_scraper.py` — Primary multi-threaded scraper. Crawls
  pagination, dedupes against existing data, parses detail pages with
  BeautifulSoup, downloads linked PDFs to `downloads/live_properties/`, and
  appends to JSONL.
- `eauctions_scraper.py` / `scraper.py` — Earlier single-threaded versions.
- `explore_eauctions.py` — Site exploration helper.
- `scraper_controls.py`, `utils.py` — Shared scraper helpers.
- `live_eauction_data.jsonl` / `.csv` — Raw all-India dataset (~49K records
  at last run).
- `scrape_errors.log` — Scraper error log.
- `downloads/` — Downloaded auction documents (PDFs, images).

## 2. Diagnostic & Data-Prep Scripts (`scripts/`)

Mixed bag of one-off utilities and the TN data-prep pipeline.

- `prepare_tn_data.py` — Filters raw JSONL to Tamil Nadu, normalizes prices
  (₹/commas → float), dates (DD-MM-YYYY HHMM AM/PM → ISO 8601), and
  downloads list. Validates file existence → `downloads_complete` flag.
  Produces `tn_auction_data.jsonl` (~4,788 cleaned TN records at last run,
  primary input for Neo4j ingestion) and `tn_download_report.txt`.
- `load_tn_to_neo4j.py` — Creates constraints/indexes and batch-MERGEs nodes
  and relationships into Neo4j Aura.
- Diagnostic/utility scripts: `check_*.py`, `debug_*.py`,
  `fuzz_pagination.py`, `find_count_selector.py`, `verify_download_fix.py`,
  `fix_extensions.py`, `compare_urls.py`, `remove_duplicates.py`,
  `dump_text.py`, `diagnose_stuck.py`, `get_keys.py`,
  `convert_to_excel.py`.

## 3. Enrichment Pipeline (`pipeline/`)

Multi-stage pipeline that turns downloaded auction PDFs into enriched graph
data.

- `config.py` — Central config: OpenRouter keys/model, Neo4j creds, scoring
  weights, decision thresholds, path constants, tracking TSV location.
- `run_pipeline.py` — Orchestrator. Runs the stages sequentially. Flags:
  `--limit N` (OCR subset), `--skip-ocr`.
- `ocr_extract.py` — Stage 1: OCRs PDFs and calls a vision LLM
  (OpenRouter / Gemini 2.0 Flash) with `prompts/extract_auction.txt` to
  extract structured auction fields. Caches per-file results under
  `cache/ocr_results/` and writes `output/extracted.jsonl`.
- `verify_and_enrich.py` — Stage 1.5: Verifies scraped fields against PDF
  extractions per auction. PDF wins on conflicts (original preserved as
  `<field>_scraped`, name added to `field_conflicts`); `enrichment.*` is
  merged, open-ended `extras` is shallow-merged. Outputs
  `output/verified_enriched.jsonl` + `output/extras_key_frequency.json`.
- `lexical_graph.py` — Stage 2: Builds a lexical graph over extracted text
  (chunks + entity mentions). Writes `output/lexical.jsonl`.
- `normalize.py` — Stage 3: Normalizes entity names (banks, locations,
  property types) against `lookups/bank_names.json`, `locations.json`,
  `property_types.json`. Writes `output/normalized.jsonl` +
  `output/normalization_report.txt`.
- `load_enriched.py` — Stage 4: Merges enriched properties, survey details,
  possession info, and geographic hierarchy into Neo4j.
- `embeddings.py` — Shared text-embedding helper (batched OpenAI embeddings,
  exports `EMBED_DIM`).
- `embed_descriptions.py` — One-shot backfill: embeds
  `AuctionProperty.description` for every property, writes the vector back
  as `p.embedding`, and creates the `property_desc_idx` vector index. Safe
  to re-run; skips existing unless `--force`.
- `cache/` — Per-document cache for OCR/LLM calls (expensive to recompute).
- `prompts/extract_auction.txt` — Prompt template for LLM extraction.

## 4. Scoring (`scoring/`)

- `auction_scorer.py` — Ten-dimensional investment scoring. Each dimension
  returns 0–100; composite is weighted avg per `SCORING_WEIGHTS`. Persists
  `Score` nodes on properties in Neo4j.

Dimensions (weights in `modes/_shared.md`):
  A Price Attractiveness 20% · B Location Quality 15% ·
  C Legal Clarity 15% · D Bank Reliability 10% ·
  E Property Condition 10% · F Timeline Urgency 10% ·
  G Due Diligence Ease 5% · H Area Price Trend 5% ·
  I Competition Risk 5% · J Yield Potential 5%

## 5. Tracking (`tracking/`)

- `auction_tracker.py` — Eight-state investment pipeline:
  DISCOVERED → SCORED → SHORTLISTED → RESEARCHING → BID_READY →
  BID_SUBMITTED → WON/LOST → COMPLETED.
  Transitions past SCORED require human-in-the-loop confirmation.
  Persists `InvestmentTracker` nodes in Neo4j + TSV mirror.

## 6. Agent API (`api/`)

- `main.py` — FastAPI app. Serves `/web` static UI and agent + feedback
  endpoints. Run: `uvicorn api.main:app --reload`.
  Endpoints:
    - `GET  /health` — Liveness probe.
    - `POST /chat` — Agent turn; returns answer, tool artifacts, and full
      `message_history` for the client to replay on the next turn.
    - `POST /feedback` — Persist a thumbs up/down on an assistant reply.
      Captures the question, answer, tool artifacts, user-agent, and a
      trimmed window of prior `context_turns` (role + content + tool
      calls, content capped at 2000 chars). Written as `:Feedback` nodes
      in Neo4j.
    - `GET  /feedback/recent` — List recent feedback; filters by
      `unresolved_only` and `rating`.
    - `PATCH /feedback/{id}/resolve` — Mark feedback resolved. Guarded by
      the `X-Resolve-Token` header matching `FEEDBACK_RESOLVE_TOKEN`;
      called automatically by the `resolve-feedback.yml` workflow when a
      fix PR is merged.
- `agent.py` — PydanticAI agent wired to OpenRouter (Gemini 2.0 Flash).
  System prompt encodes schema hints (asset_category vs property_type
  vocabularies, TN record count) and usage rules (ground every answer in
  tool results, cite auction_id, confirm state changes).
- `neo4j_client.py` — Shared Neo4j driver / `run_query` / `session`
  helpers.
- `tools/cypher_tools.py` — Agent tools: parameterized Cypher queries
  (including semantic `semantic_property_search` over the embedding
  index), scoring invocations, tracker state transitions.

## 7. Modes (`modes/*.md`)

Markdown "mode" prompts the agent can switch into:
- `_shared.md` — Shared 10-dim scoring framework.
- `scan.md` — Broad search of opportunities.
- `shortlist.md` — Narrow to candidates.
- `evaluate.md` — Deep score one property.
- `compare.md` — Side-by-side comparison.
- `deep-research.md` — Document-level due diligence.
- `report.md` — Portfolio / pipeline reporting.
- `track.md` — Move items through the 8-state pipeline.
- `refresh.md` — Re-score after new data.

## Neo4j Graph Model

Nodes: `AuctionProperty`, `Bank`, `Branch`, `City`, `State`, `Area`,
`AssetCategory`, `PropertyType`, `Borrower`, `AuctionType`, plus
enrichment nodes (`Score`, `InvestmentTracker`, `Feedback`, and
possession/survey detail nodes added by `load_enriched.py`).

Key relationships:
  (AuctionProperty)-[:CONDUCTED_BY]->(Bank)
  (Bank)-[:HAS_BRANCH]->(Branch)
  (AuctionProperty)-[:LISTED_BY_BRANCH]->(Branch)
  (AuctionProperty)-[:LOCATED_IN_CITY|LOCATED_IN_STATE|LOCATED_IN_AREA]->(...)
  (Area)-[:PART_OF_CITY]->(City)-[:IN_STATE]->(State)
  (AuctionProperty)-[:HAS_ASSET_CATEGORY]->(AssetCategory)-[:HAS_TYPE]->(PropertyType)
  (AuctionProperty)-[:HAS_BORROWER]->(Borrower)
  (AuctionProperty)-[:IS_AUCTION_TYPE]->(AuctionType)

`AuctionProperty.embedding` is indexed as the `property_desc_idx` vector
index (built by `pipeline/embed_descriptions.py`) for semantic search.

See `domain_ontology.yaml` for the full property-level schema.

## Deployment

- **Frontend** → Vercel (serves `web/` as a static site; config in
  `vercel.json`). The production API base URL is hard-coded in
  `web/index.html`.
- **Backend** → Render Python web service (config in `render.yaml`,
  installs the slim root `requirements.txt`).
- **Database** → Neo4j Aura (hosted).

## Typical End-to-End Run

    python -m scrapers.fast_eauctions_scraper    # 1. Scrape
    python -m scripts.prepare_tn_data            # 2. Clean TN subset
    python -m scripts.load_tn_to_neo4j           # 3. Load base graph
    python -m pipeline.run_pipeline              # 4. Enrich (OCR→verify→
                                                 #    lexical→normalize→load)
    python -m pipeline.embed_descriptions        # 5. Backfill embeddings
    uvicorn api.main:app --reload                # 6. Serve agent + web UI

## Feedback Loop (CI/CD)

1. User clicks thumbs down on a reply in the web UI.
2. Frontend POSTs to `/feedback` with question + answer + tool artifacts
   + trimmed prior `context_turns`.
3. A `:Feedback` node is stored in Neo4j (`resolved: false`).
4. Maintainers review via `GET /feedback/recent?unresolved_only=true`.
5. Fix PRs include `Resolves feedback: <uuid>` in the body.
6. On merge, `.github/workflows/resolve-feedback.yml` PATCHes
   `/feedback/<uuid>/resolve` (guarded by `FEEDBACK_RESOLVE_TOKEN`) so
   the item drops off the unresolved queue.
